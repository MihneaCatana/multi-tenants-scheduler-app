## Production Readiness Plan — Project Simi

Based on a thorough audit, here's everything needed. Organized by priority.

---

### 1. 🔴 Bug Fix: Refresh cookie clear path mismatch
**File:** `backend/src/controllers/auth.controller.ts:40`

The refresh cookie is **set** with `path: '/v1/auth'` but **cleared** with `path: '/auth'`. The browser may not clear the cookie on logout — it lingers for 30 days.

- Change `{ path: '/auth' }` → `{ path: '/v1/auth' }`

---

### 2. 🔴 `.env.example` — add missing production-critical variables
**File:** `backend/.env.example`

Three variables defined in `env.ts` are **not documented** in `.env.example`:
- `CORS_ORIGINS` — currently defaults to `http://localhost:5173` (wrong in production)
- `DEFAULT_TENANT_TIMEZONE` — defaults to `'UTC'`, needs explicit setting for many regions
- `BACKUP_ENCRYPT_PASSPHRASE` — currently commented-out and vague; the docker-compose requires it

Add all three with production-appropriate comments.

---

### 3. 🔴 Nginx security headers
**File:** `backend/docker/nginx-default.conf`

The nginx config serves the SPA without any security headers (Helmet covers API responses but not nginx-served HTML/JS). Add:
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- `X-XSS-Protection: 0` (disabled — modern browsers use CSP instead)

Note: `Strict-Transport-Security` and `Content-Security-Policy` are NOT added here — those should be set by the TLS-terminating reverse proxy (Caddy/nginx) that sits in front.

---

### 4. 🟡 Deeper health check (readiness probe)
**File:** `backend/src/app.ts` (line 65)

Current `/health` only returns `{ status: 'ok' }` — it doesn't verify database connectivity. Add a `/health/ready` endpoint that:
- Pings the global database (`SELECT 1`)
- Returns 200 if OK, 503 if the DB is unreachable

Keep `/health` as-is (liveness probe — just checks the Node process is alive).

---

### 5. 🟡 Root-level `.gitignore`
**File:** `.gitignore` (new, at repo root)

Create a root `.gitignore` covering OS files, editor configs, and common patterns so files at the repo root are also excluded.

---

### 6. 🟡 Nginx proxy timeouts + body size
**File:** `backend/docker/nginx-default.conf`

Add explicit timeouts and a client body size limit to prevent abuse:
- `client_max_body_size 1m` (matching Fastify's default)
- `proxy_read_timeout 30s`, `proxy_connect_timeout 10s`, `proxy_send_timeout 30s`

---

### 7. 🟡 Rate limits configurable via environment
**Files:** `backend/src/config/env.ts`, `backend/src/plugins/security.ts`, route files

Currently rate limits are hardcoded (global 200/min, login 10/min, etc.). Add:
- `RATE_LIMIT_GLOBAL_MAX` (default 200) and `RATE_LIMIT_GLOBAL_WINDOW` (default '1 minute')
- `RATE_LIMIT_LOGIN_MAX` (default 10)
- `RATE_LIMIT_REFRESH_MAX` (default 20)

Wire them into `security.ts` and the route files.

---

### 8. 🟢 Production deployment guide
**File:** `docs/deployment.md` (new)

A step-by-step production deployment guide covering:
1. Prerequisites (VPS, domain, DNS)
2. DNS setup: wildcard `*.yourdomain.com` pointing to the server
3. TLS termination (Caddy or nginx+certbot) — with a sample Caddyfile
4. Generating secrets (`pnpm generate-secrets`)
5. Creating the production `.env` with all required overrides
6. Building and deploying (`docker compose -f docker-compose.yml up -d`)
7. Running migrations (`docker compose exec app pnpm db:migrate`)
8. Seeding the admin (`docker compose exec app pnpm seed`)
9. Verifying the deployment (health checks, test login)
10. Backup verification (`docs/backups.md` already covers restore)

---

### 9. 🟢 Production `.env` template
**File:** `backend/.env.production.example` (new)

A production-ready `.env` template with:
- `NODE_ENV=production`
- `COOKIE_SECURE=true`
- `DB_SSL=true`
- `TRUST_PROXY=1`
- `JWT_ALGORITHM=EdDSA` with key placeholders
- All passwords marked as `GENERATE_WITH_pnpm_generate-secrets`
- `CORS_ORIGINS=https://yourdomain.com,https://*.yourdomain.com`
- Commented-out `BACKUP_ENCRYPT_PASSPHRASE`

This makes it crystal clear what must change from dev to production.
